# 작업 스토리 — 핵심 화면 Figma 시안 만들기 (손작업 기준)

작업: PRD와 design.md를 받아 핵심 화면을 Figma 시안으로 만든다.
최종 결과물: Figma 파일 1개 · 390×844 프레임

## 실제 순서

1. 나는 UI Bowl에서 경쟁사 레퍼런스를 수집한다.
2. 나는 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다. [멈칫]
3. 나는 분석 내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다.
4. 나는 Figma에 레퍼런스와 화면 설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다.
5. 나는 내부 관계자들과 협의하고, 팀장이 컨셉 시안을 확정한다. [멈칫] [넘김]
6. 나는 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 들어간다.
7. 나는 완성된 시안에서 토큰이나 컴포넌트가 docs/design.md를 위반한 부분이 없는지 검토한다. [멈칫]

## 게이트 위치 (멈칫)

- G1 (2번) 반영 판단: 레퍼런스가 충분한지, 포인트마다 출처가 있는지 확신이 없었다.
- G2 (5번) 컨셉 확정: 사람의 판단이 필요했다. 협의는 여러 명과 하지만 최종 확정은 팀장 1명.
- G3 (7번) 가이드 준수: 눈으로 보다 보니 색·모서리·그림자 위반을 놓쳤다.

## 되돌아간 지점

- 5번 컨펌 반려 → 3번(화면 설계)으로 복귀
- 반영 포인트가 부족했으면 → 1번(레퍼런스 수집)으로 복귀

## 에이전트 경계 (넘김)

- B1 (5번) 나 → 내부 관계자(최종 확정: 팀장): 사람 사이 넘김은 이 한 곳만 기록한다. 에이전트 분할은 R6에서 정한다.
